# 会话报错监控

## 安装

需要带 Web 客户端的 DSH 版本。可以从插件市场安装，或直接指向本仓库：

```sh
dsh plugin add github:alb233/dsh-error-monitor
```

仓库声明了 `dsh.bundle` 并附带 `cordis.patch.yml`，因此 CLI 可以直接从源码安装。
纯 ES module，无构建步骤，除 `dsh.client.inject` 里列出的宿主包之外没有运行时依赖。

## 环境要求

DSH `>=0.2.2-rc.1 <0.3.0-0`（见 `package.json` 的 `engines.dsh`）。需要 Web 客户端
及其 `conversation.view` / `sidebar.session.row.leading` 插槽，这两者随
`@deepseek-ai/dsh-client-ui-conversation` 与 `@deepseek-ai/dsh-client-ui-sidebar-right`
提供。插件在宿主内运行，不需要单独的 Node 运行时，也不访问网络。

## 适用范围与限制

本插件针对 DSH **标准模式**设计。错误识别、规则学习注入、修复标记与卡片折叠
这整条链路，都是在标准模式下验证的。其他模式（如 `dsh-ops`、`cordis` 等插件
模式）会替换或改写内置工具，并把失败包装成看似普通的结果，插件对这些信封的
识别能力有限——**可能出现抓不到失败、卡片不显示、提示不准等体验不佳的情况**。
如需完整体验，请切换到标准模式使用。

**会话规则自动注入默认关闭**：同一原因重复报错三次后「学习成会话规则并往会话里
注入提醒」这套流程是**可选**的，默认不开启。面板筛选栏里的「自动规则注入」开关
默认关，此时插件只显示卡片、不往会话里注入任何消息，需要修复时请点卡片上的
「直接修复」按钮手动处理。只有你主动打开该开关，才会启用规则学习与自动注入。

## 它显示什么

每类不同的失败一张卡，最新在前。完全相同的失败（来源、错误码、工具、路径、文案
都一致）合并成一张，标 `×N`。五类来源：

| 来源 | 事件 | 卡片携带 |
|---|---|---|
| 回合错误 | `reason.kind` 为 `error` 的 durable `turn/end`（模型/供应商失败） | 错误码、轮次、时间、供应商原文（有 `400: {...}` 信封时解析出来） |
| 工具失败 | 带 `error` 的 durable `tool/result` | 工具名与目标路径（取自匹配的 `tool/call`）、step、错误码、工具自己的话（裁掉面向模型的提示） |
| 命令失败 | `kind` 为 `error` 的 durable `command/done` | 命令名、输出文本 |
| 子智能体异常 | `source.kind` 为 `subagent-settled`、且文案不是正常结束的 durable `user/message` | 子会话 id、宿主的结算文案 |
| 运行时通知 | 尚未被覆盖的会话级 `lastAgentError` | 通知文本与首次观察到的时间 |

`client.js` 里的 `describeError()` 是唯一把记录转成一行描述的地方：卡片和只诊断
读的是同一个字符串，所以两者不会漂移。顺序是工具名、目标路径、子智能体 id、最像
人话的细节，最后退回裸错误码，让不认识的失败仍然可辨识。先剥掉 markup——一页 HTML
错误（比如 "504 … 网站请求超时"）会丢掉条件注释和内联 CSS，只留下有用的那句话。

供应商信封是原文里最丑的一处：`400: {"message":"Invalid request parameter",...}`
会被解析成 `Invalid request parameter (400)`，网关给了 `param` 就附在后面。工具失败的
句子止于面向模型的升级提示（`retry this exact operation once with sandbox_permissions…`），
完整原文仍保留在 raw 里。这两条规则分别在 `turnDetail()` 和 `stripToolHints()`。

子智能体通知没有状态字段，**文案就是状态**：宿主用 "finished and will do no further
work" 表示正常结束（丢弃——每次结算都会发，成功也发），否则是 "failed before it
finished" 之类（记为「子智能体异常」）。子会话自己的遗言（`Its closing message:` 之后）
只保留在 raw 里，既不参与判断，也不进卡片。

`turn/end` 错误还会带上最近一次完成请求的规模：失败前最新的 `assistant/message`
贡献它的 `inputTokens + cacheReadTokens`，显示成 `最近一次请求 ≈ 180.3K tokens
（输入 177,658 · 缓存 2,688）`。失败的那次请求自身不记 usage（attempt 计数器全 0），
所以这是窗口里最接近的规模线索——它能让人一眼分清"网关拒收请求"和"代码报错"。
复制详情里也有这一行；失败前没有已完成请求时不显示。

## 原因与下一步

命中了已知特征的卡，会写明原因并给一条能直接执行的处理建议（`CAUSES` → `NEXT_ACTIONS`
→ 字典里的 `cause.*` / `next.*`）。表是有序的、先命中者胜，所以具体的特征一定排在宽泛的
前面：`403 insufficient balance` 是余额问题，不是权限问题。完全匹配不上的失败不给原因行，
也不瞎猜。

真正值得留在表里的是那些会**反复出现**的：某个 provider 吐出的工具调用没有名字（或把参数
粘在名字上），本会话每一步都会这样失败——所以 `unknown tool ""` 和它连带的 `CC Safety Net`
排在所有内容类特征之前，建议直接是换模型或换路由，而不是再调一次。同一档的还有：宿主在
执行前拦下调用、改一个从没读过的文件、调用缺必填参数、压缩锚点已过期、把图喂给没有视觉
能力的模型、搜索走进 `app.asar`、状态机非法流转、跨域跳转不跟随，以及根本没连上网络的抓取。

同一次失败从第 3 次起，卡片不再把它当偶发：加一个「重试循环 ×N」标记，建议以「先别重发
这次调用」开头——同一个请求已经被证伪两次了。不到这个次数就只显示 `×N`，重复本身还只是
工具比较忙。

## 怎么读

- 标签页固定叫「会话报错」；只有左侧会话行显示未读状态。
- 某个会话有需要处理的未读失败（中断整轮、同一调用连续失败三次，或子智能体没跑完就退出）
  时，左侧那一行的状态点会换成红色警告三角；模型自己重试过去的失败不会点亮它。
- 视图内，面板顶部的红色横幅（`sticky`）统计你上次查看之后新增的数量，并提供
  「标记已读」；还有未读时，表头总数也是红的。
- 更早的失败不在实时窗口里：「加载更早记录」每次拉一页 Turn 对齐的记录
  （`session.loadOlder()`），长会话不会一次全载入。
- 完全相同的重复失败是同一个问题：卡片显示 `×N` 和首次出现的时间，保留最新一次的
  raw，复制详情列出每个 `seq`——一个吵人的工具不会把其他问题埋掉。
- 只数相同文本会漏掉另一种循环：模型换个参数、换个路径再来一次，`×N` 一直是 1。同一工具
  因同一原因失败到第三次、而参数各不相同（像停在原地试）时，这类卡片会从自愈折叠区里
  捞回来，并写一行「同一个工具、同一个原因已经出现 N 次，参数却各不相同」——先「只诊断」
  定位，再换做法，别继续重试。
- 面板默认安静：模型还能自己纠正的单步失败不进列表，收在底部「N 条模型已自行重试」的
  折叠区里，也不计入「新报错」提醒；展开后的卡片用中性灰「单步失败」徽章，不再是红色
  「工具失败」，也没有红色新报错高亮。中断整轮的错误、重复到第三次的循环、子智能体没跑完
  的结算失败都留在列表里，新证据不会被折叠隐藏。
- 列表上方的 chip 按来源筛选，最右的 chip 切换「只看未读」；横幅只统计数据里需要处理的
  记录（中断整轮、三次以上循环、子智能体异常），自愈类不计入；筛选把内容全隐藏时会明说，
  不会看起来像空会话。
- 每张卡的主排是「直接修复」（排队一条 prompt，让 agent 先读原始事件、动手修因、再原样
  重跑同一调用验证）、「复制详情」（剪贴板，不截断，含 `seq=`）、「标记已解决」。
- 次要动作收在「更多」里：「只诊断」（只分析原因、给方案，不动文件）、「重跑此步」（同工具同参数
  原样再发一次）、「发送完整原文」（把完整 raw 一起发出，最费 token，只在读不到事件时值得用）；展开状态
  在卡片间共享，连续处理一批错误不用逐张点开。
- 机理明确的失败还会显示「修复命令」：已从报错里填好端口、路径、模块、主机的命令
  （Windows 是 PowerShell，Unix 路径或 `bash:`/`command not found` 这类报错自动换成
  POSIX 版：`ss`/`lsof`、`test -e`、`command -v`、`df -h`），复制即可运行（跑命令不花 token，「直接修复」也把同一批命令交给
  agent，让修复从实测事实开始，而不是再诊断一轮）。原文里读不到的参数不会输出半截
  命令——`Stop-Process -Id <PID>` 这种会被当成指令去跑然后失败，宁可不给。命令除装依赖
  外都是只读检查，不含杀进程、建仓库这类副作用；折叠区里的卡片不显示命令块。
- 修好之后不用再回来点一下：直接修复和重跑此步都会让 agent 在重跑真正成功时于回复末尾
  写一行 `ERROR-MONITOR-FIXED seq=<n>`，面板读到这一行就把对应卡片标为已解决。没验证过的
  修复不会写出这一行，所以不会被误标；你手动标过的状态也不会被覆盖。卡片是自己消失的，
  所以自动标记时会有一条「N 张卡片已按模型的修复回报自动标记为已解决」的横幅，8 秒后自清。

## 发布前的校验

双语词典、原因表和修复命令都写在 `client.js` 里，没有任何类型检查兜底，所以漏翻一条、
签名写坏一处，构建期看不出来、用户一眼就看见。七个脚本直接读 bundle 断言真正会坏的
东西，`npm run check` 一次跑完：

```powershell
npm run check
```

- `tools/check-locale-keys.mjs`——中英 key 与 `{占位符}` 一致，每条原因都有下一步，
  没有没人引用的死文案。
- `tools/check-error-hints.mjs`——拿 52 条真实报错文本重放签名表，正则一改就误判的
  已知错误会在这里挂掉。
- `tools/check-repair-commands.mjs`——修复命令模板能从记录里填参数，且半填的命令
  永远不会显示；两张表（PowerShell / POSIX）覆盖同一批原因，Unix 路径真的会切表。
- `tools/check-fix-marker.mjs`——修复握手：模型被要求写的那行标记，以及把它变成
  已解决标记的扫描；子会话的标记必须带 `child=<id>`，否则同号的父级卡片会被误标。
- `tools/check-subagent-prompts.mjs`——子智能体那条路：卡片把子会话 id 交给 prompt、
  结算失败不被折叠、子会话的未读水位各记各的、25 个上限与每轮 5 个的分批读取都还在。
- `tools/check-main-hints.mjs`——主会话的分诊层：抖动循环按「工具 + 原因」计数并被
  拉出折叠区、卡片上有对应提示、重跑也能闭环、自动标记会播报且 8 秒自清、原因未知时
  的建议不再指向已改名的按钮、修复命令跟随失败而不是跟随宿主平台。
- `tools/check-client-load.mjs`——bundle 仍能解析并注册它的 slot。

## 审计：失败会显示成什么样

摘要只能靠读来判断，而等用户撞上一种新失败是不可接受的。这个脚本用同一套折叠规则
重放会话日志，打印每张卡和每条 prompt 会说什么——不花 token、不用点击：

```powershell
# 最新会话
node tools/audit-error-summaries.mjs

# 本机所有会话
node tools/audit-error-summaries.mjs --all

# 指定某个日志
node tools/audit-error-summaries.mjs --file <session.v4.jsonl.zstd>

# 本会话子智能体记录到的失败
node tools/audit-error-summaries.mjs --children

# 指定父会话的子智能体
node tools/audit-error-summaries.mjs --children --file <parent session.v4.jsonl.zstd>

# 重放内置夹具，不需要会话日志
node tools/audit-error-summaries.mjs --self-test
```

`--children` 默认以最新会话为父会话（`--file` 可另指），这种模式下 `--all` 会被忽略。
从未委派过子智能体的父会话会打印 `(no subagent session recorded for this session)`。

输出按来源和 `source:code` 计数，再打印每条记录的渲染文本。面板会合并的记录打印成
一行，带 `×N` 和所有 `seq`，所以审计看到的列表与读者看到的一致。脚本镜像
`describeError` / `foldErrors` / `groupRecords`；`client.js` 的提取规则一变，同一次改动
里就要更新脚本。

`--self-test` 用同一套规则重放 `tools/audit-error-summaries.fixtures.mjs` 并断言渲染
文本，规则变化会以夹具差异暴露，而不是悄悄漂移。5 个用例覆盖：供应商信封解析、
它的纯文本回退、工具提示裁剪、子智能体文案过滤（含遗言排除）、重复失败合并。

### 子智能体失败

子智能体以**独立 Session** 运行，不在父会话的事件窗口里：它的日志头带
`parentSession`、`origin: 'subagent'` 和 `delegationDepth`，宿主的会话列表里也有这些行，
只是 UI 把它们藏了起来。面板同时读两处：

1. **父会话里的结算通知**——`source.kind` 为 `subagent-settled`、`form: 'notice'`、带
   `summary` 和 `senderSessionId`（指向子会话）的 durable `user/message`。每次结算都发一条
   ——成功也发——文案是它唯一的状态，所以非正常结束的记作「子智能体异常」，其余丢弃。
   这类**不折叠**：子智能体没跑完，意味着那一支没交出结果，值得看一眼。
2. **子会话自己的日志**——`ctx.sessions.subagentAddress(id)` 把子会话 id 变成
   `SubagentAddress`，再用 `sessions.using(address, { source: 'gateway' })` 读它的窗口
   （不可用时退回 `retain` + `reference.ready` / `release()`），用与父会话同一套规则折叠，
   卡片带「来自子智能体 XXXXXXXX」徽章。子会话内部自己重试过去的失败仍进底部折叠区。
   局限与对策：只读尾窗；序号从 1 重开，所以未读水位按子会话各记一个（父会话那个水位
    对子会话没有意义，两个序号空间不可比），分组键与修复标记也都带子会话 id。每个子会话一次
    RPC，因此有 25 个上限（超出的在列表上方明说数量），并且每个 20 秒周期只轮转读取其中 5 个
    ——子会话集合变化时才一次全读；workflow 子会话不给父会话发任何事件，父会话 `topSeq` 长期
    不动，所以另靠这个周期重读，否则会永远停在首次读取。

本机实测（2026-11-23，646 个有工具失败的会话）：主会话 92 个 / 1538 条失败 / 25 条超时
（1.6%）；子智能体会话 60 个 / 146 条 / 23 条超时（16%）；最高频的一条是宿主的
`tool call timed out after 30000ms`（30 秒单次工具上限，全机 29 次）；`subagent-settled`
的失败通知只有 22 条、散在 6 个父会话里。超时属于自愈层，子智能体没跑完才是要提醒的那类。

子会话卡片上的动作也按这个前提调整：读取事件用 `session_id=<子会话 id>`；模型被要求写的
标记是 `ERROR-MONITOR-FIXED seq=<n> child=<子会话 id>`（只写 `seq` 会误标父会话里同号的卡片）；
「直接修复」不再要求「原样重跑同一调用」——那一步的会话已经结束，改为在父会话里重做同样的委派，
或直接检查改过的文件、端口与环境。

### 尚未接入的一条路径

宿主侧聚合：Host 插件的 `ctx.sessions.list()` 返回全部 live Session（不过滤 origin），
`session/event` 覆盖包括子会话在内的所有会话。最完整、也不依赖已加载窗口，但把它暴露给面板
需要 Remote 命名空间/路由，不是普通插件 API。

位置：`<workspace>/tools/audit-error-summaries.mjs`（离线体检用，支持 `--children`）。

## 数据范围

面板只通过 Web 客户端已经持有的 Session 日志镜像（`session.eventSource`）读当前会话
自己的事件窗口，加上会话级运行时通知。它不请求额外数据源、网络或宿主端点，也不往
会话日志里写任何东西。

`localStorage` 里本包的键下存四样小东西：本地已读水位（父会话一个、每个子会话各一个）；按根因分组的「已解决」标记
（上限 300 条，超出按时间淘汰）；「自动修复账本」，记住哪些 `seq` 已经收到过验证通过的
修复回报。标了已解决的报错会淡化并带绿色徽标，可以一键重新打开，也可以「只看未解决」
过滤；同根因的报错若再次发生，依然会以未读状态冒出来，标记不会吞掉新证据；你手动取消
的标记也不会被旧回报悄悄标回去。

## 面板里的按钮

顶栏最右边是「▸ 使用说明」按钮（悬停提示「每个按钮干什么」），点开在它下面展开两栏对照：
左边是卡片上的动作——直接修复、复制详情、标记已解决、更多（只诊断 / 重跑此步 / 发送完整原文）、
修复命令——加上底部折叠区；右边是顶栏与筛选里的控件：复制报告 / 使用说明 / 搜索 / 来源筛选 /
只看未解决 / 只看未读 / 全部已读 / 加载更早。它只是列名字，每条动作的含义见上一节「怎么读」，
不重复解释。

说明文字是中英双语，跟着界面语言走；默认收起，不占地方，展开后有最大高度、超出可滚动。

## 它住在哪

注册为 `conversation.view`，所以出现在会话的 View 标签行，与 对话 / 上下文 / 编队 /
统计 并列。未读三角注册到 `sidebar.session.row.leading`。没有任何面向模型的东西：
宿主半边是一个空的 `apply()`，只为让 Loader 有一行。

## 卸载行为

卸载插件会撤回 View 注册和行装饰；标签页消失，侧栏行回到它们自己的状态点。
布局的其他部分不受影响。

## 更新记录

### 1.7.0

- **修复标记终于能折叠卡片**：自动标记读取会话事件时漏解包了一层，导致 `ERROR-MONITOR-FIXED` 回报的卡片一直不进折叠区；现已修复并加了回归测试。
- **自动规则注入改为默认关闭**：重复报错学规则、往会话注入提醒这套流程改为可选开关，默认关；关闭时只显示卡片，用「直接修复」手动处理，选择权交还用户。开关是真正的滑块样式，说明文字内联显示。
- **注入改为「被接受才算数」**：规则提醒只有在会话真正接受排队消息后才写注入账本，排队被取消或失败时下次重复报错会重新提醒；防止「假注入」。
- **移除取消注入按钮**：规则一旦学习便在 UI 常驻展示。
- **聚焦标准模式**：删除 OPS / 模式替换专用兼容代码与文案，其他模式可能出现体验不佳，README 已明确说明。

### 1.6.1

- **子智能体的失败不再被静音**：子智能体没跑完的结算失败进主列表、计入横幅、点亮侧栏红三角；卡片上附一行「它自己的报错收在下方折叠区（N 条）」，指向同一次任务的细节。
- **子会话卡片能读对事件了**：卡片发出的 prompt 带的是子会话 id（`session_id=<子会话 id>`），不再拿子会话的 seq 去父会话里读；标记行也带 `child=<id>`，父会话同号卡片不会被误标。
- **子会话有自己的未读水位**：每个子会话一个，父会话已读之后子会话里新出的失败仍然算未读；存储因此从三样变四样。
- **子会话定期重读**：workflow 子会话没有结算通知，原来只挂在父会话 seq 上，会长久停在第一次读取；现在每 20 秒轮一次，每次只读新出现的和 5 个已有子会话，不把 25 个一次性 retain/release。
- **25 个上限可见**：超过上限的子会话不再被悄悄丢掉，面板会写「N 个子智能体会话没有读取（上限 25 个）」。
- **子会话的「直接修复」不再要求原样重跑**：子会话已经结束，第 3 步改为在父会话重做同样委派或直接检查改动过的文件、端口、环境，标记仍写回子会话。
- **抖动循环**：同一工具、同一原因失败到第三次而参数各不相同（换个路径再来一次）时，不再被当成自愈折叠，卡片写明它像是在原地试，建议先诊断再换做法。
- **重跑也闭环**：重跑此步成功后同样会回写标记、卡片自动标已解决；自动标记时有一条 8 秒后自清的横幅，卡片不会凭空消失。
- **修复命令跟随失败而不是跟随宿主**：Unix 路径或 `bash:` / `command not found` 这类报错自动换 POSIX 版命令（`ss`/`lsof`、`test -e`、`command -v`、`df -h`），两张表覆盖同一批 14 类原因。
- **文案**：原因未知时的建议不再指向已改名的「发回对话」，改为「更多 → 只诊断」；发送成功的提示改为「已发送给模型」。
- **工程**：新增 `tools/check-main-hints.mjs`，`npm run check` 现在七个脚本；README 校验清单同步。

### 1.6.0

- **直接修复**：卡片主排第一个按钮。排一条 prompt，让 agent 先读原始事件、动手改因、再原样重跑同一调用验证，而不是再诊断一轮。
- **修复命令**：14 类机理明确的失败给出已从报错里填好参数的 PowerShell 命令，复制即可运行、不花 token；参数读不到就整块不显示，宁可不给也不给半截；除装依赖外都是只读检查，不含杀进程、建仓库。
- **自愈折叠**：模型还能自己纠正的单步失败不再进列表，收在底部「N 条模型已自行重试」里，不计入「新报错」，侧栏也不点亮红三角；展开后是中性灰「单步失败」徽章，没有红色高亮。
- **按钮收敛**：主排保留 直接修复 / 复制详情 / 标记已解决，把 只诊断、重跑此步、发送完整原文 收进「更多」；展开状态在卡片间共享，批量处理不用逐张点。
- **修复闭环**：直接修复重跑成功后，agent 在回复末尾回写 `ERROR-MONITOR-FIXED seq=<n>`，面板据此自动把卡片标为已解决；没验证过的修复不会写，手动取消的标记也不会被旧回报改回去。
- **签名 53 → 59、用例 42 → 52**：补上 `unknown tool`（无名字、或参数粘在名字上）、`ASK_CANCELLED`、文件在读完后又变、模式替换官方工具、工作区外路径、审批关闭这几类；压缩拒绝、无视觉模型、缺凭据并入已有签名。
- **工程**：五个校验脚本搬进仓库 `tools/`，`npm run check` 一次跑完；README 改为中文单语。
