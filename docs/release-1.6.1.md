# 1.6.1 — 子智能体不再被静音，循环判定看穿换参数

这一版没有新页面，改的全是「出问题之后那一段」：子智能体报错终于会走到你眼前，重跑能自己闭环，
修复命令跟随失败而不是跟随宿主平台。

## 子智能体：从「看不见」到「看得懂」

1.6.0 会把子智能体的失败读进来，但读得不完整：结算失败被当成自愈折叠、子会话卡片的 prompt
拿子会话的 `seq` 去父会话里查、子会话的未读水位和父会话共用一个、workflow 子会话没有结算通知
所以停在第一次读取、超过 25 个子会话的部分被静默丢掉。这一版逐条修掉：

- **结算失败升级为需处理**：进主列表、计入横幅、点亮侧栏红三角；卡片上附一行「它自己的报错
  收在下方折叠区（N 条）」，让人能从「没跑完」跳到具体失败。
- **读对事件**：子会话卡片的 prompt 带 `session_id=<子会话 id>`，标记行带 `child=<id>`，
  父会话里同号的卡片不会被误标。
- **各记各的水位**：每个子会话一个未读水位，父会话已读之后子会话新出的失败仍然算未读。
- **定期重读**：workflow 子会话每 20 秒轮一次，每次只读新出现的和 5 个已有子会话；25 个上限
  不再静默——超出时面板写「N 个子智能体会话没有读取（上限 25 个）」。
- **修复方式不同**：子会话已结束，第 3 步不再要求「原样重跑同一调用」，改为在父会话重做同样
  委派，或直接检查改动过的文件、端口、环境。

## 主会话：两种循环、两种闭环

- **抖动循环**：只数相同文本会漏掉「换个参数再来一次」——`×N` 永远是 1。同一工具、同一原因
  失败到第三次而参数各不相同（像停在原地试），这类卡片会从折叠区捞回来，并写明这意味着什么：
  先「只诊断」定位，再换做法。
- **重跑也闭环**：「重跑此步」成功后同样回写 `ERROR-MONITOR-FIXED`，卡片自动标已解决。
- **自动标记会播报**：卡片自己消失时，横幅会写「N 张卡片已按模型的修复回报自动标记为已解决」，
  8 秒后自清，不留下「刚才那张卡去哪了」。
- **修复命令跟随失败**：Windows 给 PowerShell，Unix 路径或 `bash:` / `command not found` 这类
  报错自动换 POSIX 版（`ss`/`lsof`、`test -e`、`command -v`、`df -h`），两张表覆盖同一批 14 类。
- **文案**：原因未知时的建议不再指向已改名的「发回对话」，改为「更多 → 只诊断」。
