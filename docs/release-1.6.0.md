## 1.6.0

1.5.0 解决的是「为什么失败」，这一版解决「失败之后怎么办」——从只给一句话，变成能直接动手。

### 直接修复

卡片主排第一个按钮。排一条 prompt 回对话，要求 agent 不要停在诊断：先 `session_event_read` 读原始事件确认失败位置，再直接改文件 / 改参数 / 停占用进程 / 补模块 / 纠路径，最后原样重跑同一调用验证，并汇报改了什么、验证结果、还失败看哪。涉及删除、隐私、外部账号时它会停下来说明你该做什么。

同时注入现成的修复命令，让修复从实测事实开始。

### 修复命令

14 类机理明确的失败给出已填好参数的 PowerShell 命令，复制即可运行，不花 token：

| 失败 | 命令做什么 |
|---|---|
| 端口被占 | 查出监听该端口的进程 |
| 路径不存在 / 不是目录 | `Test-Path`、列父目录 |
| 缺 Python 模块 | `python -m pip install` |
| 命令找不到 | `Get-Command`、`where.exe` |
| 磁盘满 | 各盘剩余空间 |
| 不是 git 仓库 | `git rev-parse`、列目录（不再 `git init`） |
| 依赖解析失败 / 缺脚本 | `pnpm install` |
| 编码错乱 | 按 UTF-8 读前几行 |
| DNS / 连接被拒 / 证书 / 抓取失败 | `Resolve-DnsName`、`Test-NetConnection`、`curl -vI`、`curl -sI` |

两条规则：参数读不到就整块不显示（`Stop-Process -Id <PID>` 这种半截命令会被当成指令跑然后失败，比不给更糟）；除装依赖外都是只读检查，不含杀进程、建仓库这类副作用。需要判断的类别（编辑锚点冲突、4xx、沙箱拒绝）刻意不给命令，交给直接修复。

### 自愈折叠

模型收到工具失败会自己在同一轮里改参数重试，这类失败不需要人看。它们现在不进列表，收在底部「N 条模型已自行重试」折叠区里，不计入「新报错」提醒，侧栏也不点亮红三角；展开后的卡片用中性灰「单步失败」徽章，没有红色高亮。

留在列表里的只有：中断整轮的错误、同一调用重复到第三次的循环。新证据不会被折叠藏起来。

### 按钮收敛

主排从六个收成三个：直接修复 / 复制详情 / 标记已解决。只诊断、重跑此步、发送完整原文收进「更多」——前两者与直接修复重叠，后者只有在读不到事件时才值得用，且最费 token。「更多」的展开状态在卡片间共享。

### 修复闭环

直接修复重跑成功后，agent 在回复末尾写一行 `ERROR-MONITOR-FIXED seq=<n>`，面板读到就把对应卡片标为已解决。没验证过的修复不会写；你手动取消的标记不会被旧回报改回去（`localStorage` 里有一份账本，上限 300 条）。

### 签名与用例

原因是 53 条、用例 42 个 → 原因是 59 条、用例 52 个。新增：`unknown tool`（工具名为空、或参数粘在名字上）、`ASK_CANCELLED`、文件在读完后又变（stale version）、模式替换官方工具、工作区外路径、审批关闭这 6 条；压缩被拒、无视觉模型、缺凭据并入已有签名。本机 633 个会话、1669 条失败重放后，未识别从 80 种降到 50 种，剩下的多是业务层错误（项目 id 缺失、状态机非法、400 参数），不硬塞原因。
